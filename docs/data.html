Decision 1

Store the path, not the picture

A SQL Server data page is only 8 KB. Putting 13 GB of DICOM binaries into the database would push the useful index and table pages out of memory. We compared the four storage options and kept images on disk.

Decision 2

Why the difference?

  • Minimal logging. BULK INSERT and bcp with TABLOCK write far less log than row-by-row inserts.
  • Identity column trap. The 5-column CSV does not match the 6-column table (Msg 7301); an updatable view solves it without format files.
  • Reproducibility. The finished database is shared as a .bak backup (53 MB), which is also how you restore it in the repository guide.

What this provesKeeping binaries outside the engine keeps the buffer pool for relational work and shrinks the database 250×. Strict typing makes later index and optimizer experiments meaningful.
Honest limitSQL Server has no approximate-nearest-neighbour index, so similarity search (Q3) is a full scan of 48,345 vectors. A dedicated vector store would be the production choice.
